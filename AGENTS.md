# AGENTS.md

omastats: analytics dashboard for the Omarchy plugin catalog. Hono Worker +
D1 + Drizzle API with a React SPA frontend (TanStack Router + Query, coss
ui, dither-kit charts), two cron triggers, edge-cached API, deliberately
tuned to Cloudflare's Free tier (see Budget discipline).

## Work here

No git repo: no history, no rollback. Read before editing, verify before
deploying. `wrangler.jsonc` and `package.json` are the environment truth
(scripts, bindings, crons); `README.md` documents the API routes.

- Typecheck: `bun run typecheck` (`tsconfig.worker.json` + `tsconfig.client.json`:
  the Worker runs DOM-less with hono/jsx, the React app needs DOM lib and
  `jsxImportSource: react`). `tsconfig.json` itself is vite-facing only:
  it must not exclude client files or vite's tsconfig-paths resolution
  breaks `@/*` in the client build. Per-file
  `/** @jsxImportSource react */` pragmas on client TSX keep the Vite build
  on React regardless of tsconfig's hono/jsx default. `bun run build` does
  **not** typecheck.
- Lint: `bun run lint` (biome, config in biome.json). Biome is also the
  formatter: match its style in new code: tab indents, double quotes,
  trailing commas, 120-col lines, semicolons.
- Self-checks: `bun src/lib/snapshot.selftest.ts` (assert-based). Non-trivial
  new logic gets one; extend it when snapshot/`current_*` logic changes.
- Manual poll in dev (miniflare): heavy = `curl -X POST
  http://localhost:5173/cdn-cgi/mf/scheduled`; light = same with
  `?cron=*/30%20*%20*%20*%20*`. Prod: `POST /api/admin/snapshot` with header
  `x-admin-token: <ADMIN_TOKEN secret>`.
- Schema change → `bun run db:generate` → `db:migrate:local` →
  `db:migrate:remote`. Remote applies immediately: additive columns are safe,
  destructive changes are not.
- `worker-configuration.d.ts` is generated by `bun run cf-typegen`, never
  hand-edited. Commit it (Cloudflare recommends committing the generated
  types); regenerate after any `wrangler.jsonc` change.

## Architecture (data flow)

1. **Heavy cron** `0 */6 * * *`: `runSnapshot()` (src/lib/snapshot.ts).
   Fetches catalog.json (3.6 MB, ~1580 plugins) + stats.json (98 KB),
   zod-validates both, upserts `plugins` (metadata + `current_*`), appends one
   `plugin_snapshots` row per plugin, diffs against the previous snapshot into
   `verification_events` / `update_events`, prunes snapshots older than 90 days.
2. **Light cron** `*/30 * * * *`: `pollNewPlugins()` (src/lib/light-poll.ts).
   Fetches catalog.json, inserts rows only for new plugin IDs (fresh count).
   Cheap on purpose: no zod, no per-plugin loop, no snapshot writes.
3. **API**: src/lib/api.ts. Every GET /api/* response is edge-cached via the
   Cache API (`s-maxage=3600`); `/api/health*` stays uncached; only 2xx stored;
   `x-cache: HIT|MISS` header for observability. Crons are dispatched by
   `ctl.cron` in `scheduled()` (src/index.tsx).
4. **Frontend**: the same Worker serves the SPA via a catch-all GET route in
   src/index.tsx renders the shell (`src/renderer.tsx` loads `/src/client.tsx`),
   routing happens client-side (TanStack Router, generated `src/routeTree.gen.ts`;
   never hand-edit it).

## Frontend (client code)

- **Two bundles, one build**: the `client` Vite environment (src/client.tsx +
  src/routes + src/components) and the `omastats` worker environment. `@/`
  resolves via `resolve.tsconfigPaths`; `tsconfig.json` must NOT exclude client
  files or that resolution breaks. Client JSX files need the per-file
  `/** @jsxImportSource react */` pragma (root tsconfig defaults to hono/jsx
  for the worker); worker files must NOT have it.
- **Wire contract**: src/lib/api-types.ts is the single source of truth for API
  response shapes. api.ts annotates every `c.json()` payload with
  `satisfies XResponse`; client hooks (src/lib/queries.ts) import the same
  types. Changing a response shape changes api-types.ts; tsc catches drift on
  the server side.
- **UI components** land as owned source files: coss ui via
  `bunx --bun shadcn@latest add @coss/<name>` (src/components/ui/), dither-kit
  charts via `bunx --bun @dither-kit/cli add <chart>` (src/components/dither-kit/,
  lockfile-tracked). Charts: pick `bloom="low"` and dither colors from
  `palette.ts`; parts (`Area`, `XAxis`, …) import from individual files, not
  the chart root. coss usage rules live in `.agents/skills/coss/`.

  ⚠️ **CLI-installed files ship WITHOUT the `/** @jsxImportSource react */`
  pragma** (button, gradient, kbd all hit this). Add it to every new
  client-rendered `.tsx` file immediately after install. Without it,
  vite/esbuild falls back to the root tsconfig's `jsxImportSource: "hono/jsx"`
  and the component's JSX compiles to Hono nodes, which React rejects at
  runtime with `Objects are not valid as a React child (found: object with keys
  {tag, props, key, children, isEscaped})`. After any install, run:
  `for f in $(find src/components src/routes -name "*.tsx"); do head -1 "$f" | grep -q "jsxImportSource react" || echo "MISSING: $f"; done`
  (dither-kit also occasionally overwrites palette.ts/pixel.ts/lib.ts: same
  0.1.0 content, safe; it prompts, answer yes).
- **Pages** live in src/routes/ (file-based routing, `createFileRoute`).
  Loading = Skeleton, errors = toast via `useErrorToast` (src/lib/queries.ts).
- **Responsive traps**: a `Table` inside a grid/flex section needs the
  section at `min-w-0` — `min-width: auto` stops the cell shrinking below the
  table's intrinsic width, so the page overflows horizontally and the table's
  own `overflow-x-auto` never engages. Header nav links are `whitespace-nowrap`
  and only fit from `lg` (below that the hamburger sheet takes over); moving
  the breakpoint back to `md` re-breaks the header — "Ecosystem Health" wraps
  to two lines in the fixed-height bar.

## The mirror

`plugins.current_*` mirrors each plugin's latest snapshot row; the heavy poll
writes both in one upsert. Current-state reads (leaderboards, authors, broken,
plugin-list `latest`) come from `plugins.current_*`, never from
`plugin_snapshots`: the "latest per plugin" query is a full index scan.

- New list/leaderboard routes read `plugins`; keep snapshot reads (trending
  history, `/plugins/:id`) time-bounded.
- Responses strip `current_*` via `withoutCurrent()` in api.ts; keep it that
  way (the frontend contract is the pre-denormalization shape).
- Light-poll-inserted plugins have NULL `current_*` until the next heavy poll;
  current-state queries filter `isNotNull(currentSnapshotAt)`.
- Changing snapshot columns changes three places together: the snapshot write,
  the mirror columns, the upsert.

## Budget discipline (Workers Free + D1 Free)

- **CPU**: 10 ms/invocation cap, enforced leniently by frequency. The heavy
  cron (~730 ms) survives only because it runs 4×/day. Extra freshness goes
  through a new cheap cron, never by speeding up the heavy one. The light poll
  (48×/day) must stay under the cap: no full-zod catalog validation, no
  per-plugin work.
- **D1 free caps**: 5M rows read/day, 100k rows written/day, 50 queries per
  invocation, 500 MB database. Heavy poll ≈ 3.2k statements and ~49 batch calls
  per run (near the query cap; new work there must merge queries, e.g. batch
  the latest-reads into one `db.batch` call); light poll ≈ 0–2 statements.
  Retention holds snapshots at ~90 days × ~1580 ≈ 142k rows.
- **Cache hits save D1 reads, not CPU**: the Worker still runs to check the
  Cache API.
- **Aggregate endpoints** (`/api/stats/categories`, `breakdown`, `heatmap`,
  leaderboard `sparkPoints`) are 1–2 queries each and edge-cached 1h; keep
  new aggregate work in one GROUP BY / batch rather than paging the client.
